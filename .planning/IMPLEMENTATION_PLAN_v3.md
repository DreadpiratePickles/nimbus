_Assembled 2026-10-09 from the council (`docs/council/`) under the chairman's binding decisions (`docs/council/decision.md`, "DEC" below). Supersedes `.planning/IMPLEMENTATION_PLAN_v2.md`, which stays as history (its §1 positioning is kept in §1 here). Where this plan and any stage-1 answer disagree, DEC wins, then the stage-2 corrections, then the stage-1 text._

**How to use this plan.** Every item names an owner package set, a failing-test-first acceptance test and a track. A track is one Opus agent working only inside its package set; an independent Opus verifier re-probes each track before acceptance (the pattern that caught D1–D8 in Verification 2). Implemented ≠ deployed ≠ verified: a capability is "shipped" only when it meets its best-in-class bar in §2 and passes its acceptance test on the lab (local, and live where marked). Below that bar it is labelled `experimental` in `docs/checks.md`/README and stays out of any comparison table (B §6.0).

## 1. Positioning and claims

**Positioning (kept from plan v2 §1).** nimbus is the open, local-first security graph. It ingests the findings teams already have (Prowler, Checkov, Trivy, Steampipe, its own collectors), reduces them to the few attack paths that reach crown jewels, and opens the pull request that closes them. Published scoring, no SaaS, bring-your-own model, signed releases. Three wedges in order of investment: (1) paths from everything; (2) fix the path, in the PR (plan-time path diff, deterministic IaC fixes, verified closure — the distribution engine); (3) local-first and verifiable. Supporting: compliance evidence, a read-only MCP server, one cost card. North star: attack paths closed through merged nimbus PRs per week (measured in §8). Near-term target from plan v2: 100 named adopter organisations before 10k stars.

**What changed with the council (DEC).** Truth before wedges is now enforced by the data model: the graph becomes inventory-first and typed, permission edges carry statements from a real IAM evaluator, attack paths become Issues with stable ids, and every path is labelled `verified | inferred | hint`. Distribution plumbing runs now; launch events wait for Phase 0 exit; the plan-time diff is built in parallel but launched publicly only after evaluator v1, the noise estate and a live run.

nimbus-closes-paths: <N>
nimbus-issues: <path-issue-id>[,<path-issue-id>…]
