# nimbus gap analysis: what to build, in what order, and what not to build

_Written 2026-10-09. Decision document. Companion to [`competitive-feature-matrix.md`](competitive-feature-matrix.md) (capability IDs such as `AP6` or `RM4` refer to rows there)._

**Inputs.** The four cluster docs under `docs/research/competitors/`, `docs/research/competitors.md` (BASE), `docs/research/nimbus-capability-inventory.md` (INV; `§n` and "defect n" refer to its sections and its top-20 list), `.planning/IMPLEMENTATION_PLAN.md` (PLAN), `.planning/PROJECT.md`, `CLAUDE_CONTEXT.md`.

**Strategy input.** `docs/research/strategy-how-to-win.md` (STRAT) **was present** when this work started and was re-checked at the end (file timestamp 2026-10-09 18:02). Its recommended wedges were used to weight Buyer impact and Differentiation scores in §c:
1. **Paths from everything** (wedges a+b+i): ingest Prowler/Checkov/Trivy/Steampipe plus native collectors into one graph; published deterministic score; min-cut fix set; ingest content, don't rebuild it.
2. **Fix the path, in the PR** (wedges c+h): plan-time "this PR opens/closes N paths"; deterministic fixes first; LLM fixes only behind validate + re-scan + no-widening.
3. **Local-first and verifiable** (wedge g): single binary, offline report, BYO model, signed releases, read-only roles.
STRAT demotes compliance evidence, SQL/NL and cost to supporting features, and puts "run nimbus end-to-end against a real open lab and publish the result" before everything.

**Ground rule carried from INV.** Nothing in nimbus has run against a live AWS, Azure or GCP account (§18, `.planning/STATE.md:4`). Every "real" below is real against fakes. Every scored number below is a judgement, marked as such; no market number is invented.
