## 5. What all four missed

1. **Licence of the content they all want to import.** Prowler's compliance JSONs are Apache-2.0, but the CIS Benchmark control text they embed is CIS-licensed (attribution, non-commercial redistribution terms). An RFP buyer's legal review will ask; redistribute requirement *ids and mappings*, link the text, and record the decision in `docs/`.
2. **What leaves the machine for the LLM.** Every "zero egress except cloud APIs and the chosen LLM" exit criterion sends resource names, ARNs, tags and policy fragments to a third party by default. That is a data-residency row (rfp.wiki) and, through the MCP `sql` tool, an exfiltration channel for prompt injection — B and D guard tool *calls*, not data *egress*. Needs a documented data-flow, a redaction/allowlist layer, and a local model as the default for sensitive estates.
3. **The nimbus database is the attacker's map.** B and D propose storing raw provider JSON and configuration history; nobody proposes at-rest encryption, retention/`purge`, or CI hygiene (never upload the DB as a workflow artefact). A red-teamer steals `cloud-posture.db` from a laptop or runner and has every path pre-computed.
4. **Adversarial naming.** Crown-jewel globs and `looksSensitive` are attacker-influenceable: name the bucket to avoid `*prod*`. C critiques the heuristics but not the adversary; the confidence label should treat name-derived criticality as `heuristic` and the registry/DSPM labels as the only path to tier 4.
5. **TCO for the Commercials row (24%).** "Free" is not zero cost: compute for scheduled scans, API call volume per account, maintainer time, support. No response proposes a TCO page or an API-call/time estimate per 100 accounts; Wiz's buyers will ask.
6. **Azure and GCP are stubs in practice.** All four are AWS-first; the Azure/GCP labs are "stubs", there is no Defender-for-Cloud / Azure Policy / GCP org-policy ingestion story, and a Microsoft-shop buyer tests Azure parity first. B schedules Azure/GCP live labs for Q1 2027 but no scenario depth; nobody budgets Azure/GCP scenario authoring (S09–S11 are three of fourteen).
7. **Collection-time scale and throttling.** D covers traversal; nobody covers collection on 500 accounts: pagination budgets, concurrency (Verification 2: `scan.parallel` unset → 1), incremental collection beyond `verify`, and the cost of `GetAccountAuthorizationDetails` org-wide.
8. **Independent security assessment of nimbus itself.** Scorecard and signing answer "is the release trustworthy", not "has the code been audited". A buyer substituting for SOC 2 will ask for a third-party review (OSTIF/CNCF audit path) and a CVE/advisory process; neither appears.
9. **Trust kit scope.** SBOM, signing and SLSA cover the Go binary and image; the Python wheel and the VS Code extension — both execute on the operator's machine — are unsigned and un-SBOM'd in every plan.
10. **First-scan triage.** "Noisy first scans" is a repeated buyer complaint in the matrix. B's `--baseline` and mutes help in CI, but no response defines the first-run default on a 50-account estate: paths-only, top-N, Issues not findings, with everything else behind a flag.
