## 5. What all four missed (RFP buyer or red-teamer)

1. **The nimbus database is the most valuable file on the laptop or CI runner.** D's `resource_versions(config_json)` and A/B's "raw provider JSON stored with call + timestamp" put every policy document, trust relationship, SG rule, Lambda environment and user-data script into an unencrypted SQLite file (plus `risk.json` at 0600). Nobody proposes at-rest encryption, an attribute redaction policy for collected fields that commonly carry secrets (Lambda env, EC2 user data, container env, CloudFormation parameters), retention, or a `nimbus export --redacted` for support bundles. A red-teamer asks for the `.db` first; an RFP's "data residency and tenant controls" row includes the tool's own store.
2. **Plan-time diff and PR comments in public repositories disclose topology.** "opens 1 path to `s3://customer-pii`" posted by the Action on a fork PR tells anyone who can open a PR which bucket holds PII and which SG fronts the admin host. `terraform show -json` plan output also carries non-`sensitive` values (ARNs, CIDRs, sometimes credentials in `user_data`). The Action needs: redaction of crown-jewel identifiers in comments on public repos, a `pull_request_target`-safe mode that never runs on fork-supplied plan JSON, and plan JSON treated as untrusted input (D3 showed one hostile `.tf` kills the process). None of the four names this.
3. **Eventual consistency makes `verify` flap.** IAM and S3 policy changes propagate over seconds to minutes; B's item 7 reopens the ticket immediately when "mutate nothing → still failing". Without a bounded retry window (`verify --wait 5m`, exponential backoff, "pending verification" state) the first live `verify` after a merge will reopen tickets that are actually fixed — the exact "appear and disappear" complaint the Issue model is meant to end.
4. **What leaves the machine when the copilot is used.** BYO-LLM and offline mode are covered, but no one provides the data-flow statement a DPA review asks for: which fields (resource names, tags, policy JSON, finding text) are sent to the model, whether tags are redacted, and a `--redact-llm` default. "Zero egress except the chosen LLM" is a loophole the size of the inventory.
5. **Licence hygiene of ported content.** Prowler (Apache-2.0) is fine; PMapper is AGPL (GAP O16) and C proposes using its test patterns; pathfinding.cloud, Kubescape controls and Cartography schema each need a `THIRD_PARTY_NOTICES` entry and a per-rule `attribution` field (A/D ask for attribution, nobody names the licence check in CI).
6. **Python supply chain.** Track E signs the Go binary and image; the Python layer ships via pip with no PyPI attestations (Sigstore/PEP 740), no pinned lock in the plan, and A's "second install" risk is noted but not closed. After the KICS and Trivy incidents an RFP asks about *every* artefact.
7. **Collection-side scale and cost.** D covers traversal scale; nobody covers collector scale: per-service API rate limits across 50 accounts, pagination budgets, incremental collection, `CloudTrail LookupEvents` cost for right-sizing, scan-duration SLOs and a `--budget` cap. Cyera's documented weakness ("very large data estates report scalability and performance concerns", CA :187) is the buyer's standing worry.
8. **The read-only policy will grow and nobody prices it.** Probes need `iam:SimulatePrincipalPolicy` and Access Analyzer; right-sizing needs CloudTrail and last-accessed; org enumeration needs `organizations:*` reads. TS3 should include a published policy diff per release and a `TestReadOnlyPolicies` rule that any new IAM action is justified in the changelog — otherwise "the security tool that cannot hurt you" quietly becomes the tool with the broadest read role in the account.
9. **A correction and disclosure policy for false criticals.** `score_version` and `docs/scoring.md` changelog cover formula drift; nothing covers "we reported a wrong critical path in release X: here is the rule, the fix and the affected ids". Prowler's catalog integrity test is the nearest precedent; an RFP buyer who has been burned by Wiz tickets will ask how retractions are communicated.
10. **Windows and air-gapped operators** get one line (A item 2, PLAN O55). The RFP checklist's "data residency" buyers are the ones on air-gapped jump hosts; `collect`/`evaluate` offline equality is in PLAN Phase 1 item 6 and only D (L4) schedules it.
