# Council question (2026-10-09)

nimbus is an open-source (Apache-2.0), local-first CSPM/CNAPP: Go core (collectors, security graph, attack paths, SQL store, IaC patcher/PRs, compliance packs, alert sinks, HTTP API, cwm-look dashboard) + Python intelligence layer (reports, copilot, plugin SDK). Owner goal: "a real competitor in the CSPM niche — the complete package", beating Prowler/ScoutSuite on visibility and Wiz/Lacework/Prisma on price.

State today (all verified with executable evidence, nothing run against a live cloud yet): see .planning/IMPLEMENTATION_PLAN_v2.md §3 Phase 0 (done this session), docs/benchmark.md (ground-truth lab: recall 12/12, recall@7 10/12, precision 95%), docs/research/nimbus-capability-inventory.md (+ "Remediated"), docs/sessions/2026-10-09-cwm-ui.md (every track's evidence).

Research available: docs/research/strategy-how-to-win.md, docs/research/nimbus-gap-analysis.md (67 scored opportunities), docs/research/competitive-feature-matrix.md (91 capabilities × vendors), docs/research/competitors/{cnapp-leaders,platforms,open-source,compliance-and-adjacent}.md.

**The question:** How should nimbus best move forward from here to adopt everything the market leaders do that makes them win, and compete as the complete package — while staying open-source, agentless, local-first and buildable by a very small team with AI agents? Give: (1) your verdict on IMPLEMENTATION_PLAN_v2 (what it gets right/wrong), (2) what is still missing for "complete package" status in the eyes of a buyer running a CSPM/CNAPP RFP in 2026, (3) a sequenced 12-month roadmap (quarters) with the 5 bets you would make and the 5 things you would explicitly cut, (4) the first 10 engineering items for the next 2 weeks, each with an acceptance test, (5) the biggest risk you see and how to de-risk it.

**Added by the owner:** produce a complete **implementation plan** — the plan that gives nimbus the most features of any tool in the niche and makes it the best one — not only a critique. Structure it as: capability map (every capability the leaders have, grouped), for each capability: what "best in class" is (cite the research), what nimbus ships today, the design nimbus should adopt (packages/files in this repo), effort, dependencies, acceptance test; then the sequenced plan (phases → tracks that can run in parallel with AI agents), the exit criteria per phase, and the competitive claim each phase unlocks ("nimbus is the only open-source tool that…"). Be concrete enough that engineering agents can execute from it without further questions.

**Owner clarification:** "and the best features too not just a lot of them" — the plan must make nimbus have both the broadest capability set in the niche AND the best implementation of each capability (precision, depth, UX, evidence), i.e. best-in-class per capability per the feature matrix, not a checkbox count. Rank every capability by how much "best-in-class" would differentiate nimbus and say what best-in-class concretely means for it.
